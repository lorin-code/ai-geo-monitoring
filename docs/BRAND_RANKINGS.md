# 品牌排名

入口：GEO 工作台侧栏「品牌排名」，或报告中心的「品牌排名」链接。

1. 选择 1–50 个已有有效分析数据的品牌项目。仅展示当前账号可访问的未归档项目。
2. 选择近 7、30 或 90 天、一个监测平台、排序指标和排序方向。
3. 点击「计算排名」。系统优先复用对应周期的最新报告；缺失或过期时自动汇总已有监测数据生成报告。

支持品牌提及率、平均声量占比（SOV）、引用率、推荐率、平均排名。前四项默认从高到低，平均排名默认从低到高，也可以手动修改方向。

## 统计口径

- 周期和报告中心一致：以服务器本地日历日计算，包含今天，从周期首日零时到本次计算时间。
- 每个品牌使用一份对应周期的项目报告，读取 `summary.platforms` 中所选平台的数据，不混用全平台汇总，不平均多份历史报告。
- 当报告周期首日不同、有效分析数变化、出现新数据或指标更新时，自动重建报告。相同条件下的数据没有变化时复用已有报告。
- 无有效分析数据或缺少有效平均排名的品牌不参与该指标排名。真实的 0% 参与排名；未提及造成的平均排名 0 表示无有效排名，展示为「—」。
- 相同指标值并列，后续名次跳号，例如 1、1、3；并列行按项目 ID 稳定排序。
- 各品牌样本量可能不同，表格同时显示有效分析数和报告生成时间。单个品牌生成失败不会阻断其他品牌，重新计算可重试。
- 自动生成仅调用现有报告汇总服务，不调用大模型、不启动新的检测。生成的报告可在报告中心查看。
- 归档项目不参与自动生成和排名；普通用户只可查询自己的项目，管理员可查询所有未归档项目。选择中存在无权访问或已归档项目时，整批请求在写入前被拒绝。

## 接口

均需登录，与 GEO 项目接口使用相同的鉴权。

- `GET /api/brand-rankings/options`：可选品牌、平台及指标。
- `POST /api/brand-rankings/calculate`：计算排名并按需生成报告。

请求示例：

```json
{
  "project_ids": [1, 2],
  "days": 30,
  "platform": "deepseek",
  "metric": "brand_mention_rate",
  "order": "desc"
}
```

响应包含实际筛选条件、计算时间、自动生成报告数、参与排名品牌数，以及每个品牌的指标、名次、报告 ID、报告时间和未排名原因。

回归测试：`node --test tests/BrandRankingService.test.js`（在 `backend` 下执行，使用隔离的 SQLite 内存数据库）。
